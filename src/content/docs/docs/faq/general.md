## ZIGNOS は既存ディストリビューションの派生ですか?

いいえ。独自のパッケージマネージャ **zpkg** と独自のレシピツリーで、ツールチェーン
から最終システムまでを組み立てています。特定の既存ディストリビューションの
仕組みをそのまま使うことはしていません。

## 対応アーキテクチャは?

x86_64 のみです。BIOS / UEFI の両方で起動できます。ARM など他の
アーキテクチャは現時点の対象外です。

## サーバーでも使えますか?

CLI の最小ベースなので、サーバー用途を想定した構成も可能です。ただし
SSH / DHCP / ファイアウォールなどは最初から入っていないため、自分で
`zpkg install` して有効化する必要があります。

## デスクトップは必須ですか?

いいえ。stage3 と既定のイメージは CLI のみです。KDE Plasma 6 は
`desktop/` から任意で追加します。CLI だけで使う場合、Qt や Mesa は入りません。

## 更新はどうやって受け取りますか?

ローリングリリースです。`zpkg sync` でレシピを更新し、`zpkg upgrade -p` で
差分を確認してから `zpkg upgrade` を実行します。チャンネルを切り替える場合は
ダウングレードを含むことがあるため、必ず差分を確認してください。

## binpkg リポジトリは公開されていますか?

現在、公開 binpkg リポジトリは運用していません。レシピツリーは公開されており、
各自の環境でソースからビルドします。ローカル binpkg は既定では作成しませんが、
`BUILD_BINPKG=1` でビルドキャッシュとして残せます
([zpkg 設定](/docs/zpkg-config/))。

## ライセンスは?

このサイトの文章とロゴは Studio NØSa. に帰属します。ZIGNOS のソフトウェアは
各リポジトリ・各パッケージのライセンスに従います。個々のレシピのライセンス情報は
現在整備中です。

## 開発に参加できますか?

はい。公開している `zignos-recipes` と公式サイトは GitHub で改善できます。
詳しくは [コントリビュート](/docs/contributing/) を参照してください。
