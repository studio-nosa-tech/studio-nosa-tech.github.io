ZIGNOS は「配られた OS を選ぶ」のではなく、「自分の OS を組み立てる」ための
土台です。便利さのために中身が見えなくなるのではなく、入れたもの・変えたものを
自分で説明できる状態を目指しています。

## ゼロから組み立てる

ツールチェーン、libc、ベースシステム、パッケージマネージャまで、ビルド手順を
リポジトリとして持ちます。既存ディストリビューションの派生ではなく、独自の
レシピツリーと **zpkg** で最終システムを組み立てます。

## 最小ベース

stage3 はカーネルと GRUB を含まない、chroot 可能な最小ベースです。エディタ、
SSH、DHCP、WiFi、man は最初から入っていません。必要なものを、必要なだけ
`zpkg install` で追加します。デスクトップも同じ考え方で、`desktop/` から
任意に導入します。

## レシピが唯一の真実

パッケージの版、依存、ビルドフラグ、パッチはレシピに書きます。ビルドした
バイナリはキャッシュし、再ビルドを速くします。レシピはシェルスクリプトで、
特別な DSL を覚えなくても読めることを重視しています。

## 独立したパッケージ管理

zpkg は USE フラグ、スロット、world、binpkg、トランザクション、Ed25519 署名、
bubblewrap によるビルド隔離、provenance / SPDX SBOM を持ちます。パッケージの
来歴を記録し、あとから検証できることを大切にしています。

## OpenRC

init は OpenRC です。サービスは opt-in で、何を起動するかを自分で選べます。
デスクトップでも systemd へ移行せず、elogind / PAM / polkit を組み合わせて
Wayland セッションを支えます。

## ローリングリリースと3チャンネル

各チャンネルの HEAD が現在のリリースです。安定重視の `stable`、最新安定版の
`testing`、RC / beta を含む `unstable` を用意し、変更は
**Unstable → Testing → Stable** の順に検証します。

## 透明性と再現性

ビルドログ、レシピ digest、依存環境、SOURCE_DATE_EPOCH を記録し、同じ入力から
同じ成果物を目指します。リリース情報は `release.json` に集約し、サイト・
ダウンロード・インストールガイドが同じデータを参照します。
